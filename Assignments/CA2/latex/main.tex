\section{Introduction}
% ============================================================

This report presents the implementation of \textbf{Ashpaz}, a real-time food ordering and
delivery platform developed as part of Assignment 2 for the Introduction to Data Science
course. The project is structured around three interconnected layers that together form a
complete data engineering pipeline.

The first layer (\textbf{Q1}) focuses on relational database design and analytics. Using the
Zomato restaurant dataset, we normalize a flat CSV file into a structured schema, load the
data, and answer business-critical queries covering delivery statistics, pricing tiers, and
neighborhood performance.

The second layer (\textbf{Q2}) introduces \textbf{Apache Kafka} as a distributed messaging
backbone. A Kafka consumer reads from the \texttt{ashpaz.order} topic, performs stateless
validation on each incoming order event, and routes messages to either \texttt{ashpaz.valid}
or \texttt{ashpaz.error\_log} depending on data quality. This section also addresses key
theoretical questions on Kafka's architecture, stateless vs.\ stateful processing, and the
distributed commit log model.

The third layer (\textbf{Q3}) implements a \textbf{PySpark} processing layer with both batch
and real-time components. The batch jobs analyze historical order data for revenue insights
and peak-hour patterns, while the streaming application connects to the Kafka consumer and
performs windowed micro-batch aggregations with checkpoint-based fault tolerance.

The data generator (\texttt{Ashpaz.py}) simulates realistic order traffic — including
intentional noise such as invalid phone numbers, price anomalies, and spam user behavior —
providing a robust test environment for the entire pipeline.
